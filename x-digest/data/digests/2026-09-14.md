- **作者**: @chasen_liao
- **时间**: 09-13 17:24（北京时间）

### 2. Codex 用 `apply_patch` 实现编辑文件工具：五层架构拆解
- **作者**: @verysmallwoods
- **时间**: 09-13 08:48（北京时间）
- **链接**: https://x.com/verysmallwoods/status/2098936857731985419 （配套长文：https://x.com/compose/articles/edit/2098935884049461253）
- **内容**: 作者拆解 Codex 的编辑文件工具：表面只是"模型给修改、工具写文件"，中间其实隔着五层——模型先用一种 patch 语言描述修改计划；解析器把文本转成结构化 hunk；验证阶段读旧文件算新内容；安全层收集所有受影响路径；执行器再按顺序交给文件系统。核心观点："大模型擅长生成文本，文件系统只接受确定的读/写/删操作，两者之间该用什么语言衔接"是 agent 开发者值得学习的课题。

### 7. LLM 为什么缓存 K 和 V，却通常不缓存 Q？
- **作者**: @dongxi_nlp（@dotey 转发）
- **时间**: 09-13 09:22（北京时间）
- **链接**: https://x.com/dongxi_nlp/status/2098945504289669481
- **内容**: 一篇讲清 KV cache 的科普长文：把长文档交给 AI 总结时，难道每生成一个 token 都要把越来越长的全文从头算一遍？文章解释了 prefill 阶段建立各层 KV cache 的过程，以及"为什么保留 K 和 V、却通常可以用完就放下 Q"——因为新位置的 Q 才参与对历史 K/V 的注意力计算，历史位置的 Q 不再被需要。
